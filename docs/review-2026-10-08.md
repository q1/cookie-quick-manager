# Independent rewrite review

The implementation was reviewed directly after CodeRabbit could not complete
its review. The review covered cookie identity and transfers, browser mutation
boundaries, asynchronous interface state, permissions, and build packaging.
Findings were reproduced before being fixed; a passing demo was not treated as
evidence for native browser behavior.

## Findings addressed

| Finding                                              | Trigger and impact                                                                                                                                                                | Correction                                                                                    |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Firefox returns a different cookie after a write     | Same-named domain and host-only cookies coexist. A host-only edit could treat its sibling as the saved record and delete that sibling during rollback. Reproduced in Firefox 151. | Resolve the written record by its complete identity; never delete an unverified return value. |
| Concurrent extension pages bypass the mutation queue | Two pages edit the same baseline concurrently. Both could pass the stale check before either write completed.                                                                     | Coordinate cookie mutations in the background context.                                        |
| Concurrent preference changes lose protection        | A popup and workbench write settings from separate snapshots. A theme update or another protection change could overwrite protected identities.                                   | Coordinate preference writes and apply protection as atomic additions/removals.               |
| Script injection errors look like successful cleanup | The browser resolves an injection result containing an error, or the source navigates before execution. The UI could report local storage cleared without clearing it.            | Require an explicit acknowledgement from the expected main frame.                             |
| Typing during a pending save is overwritten          | A user keeps editing while a save is in flight; the response replaces the newer draft.                                                                                            | Disable draft and mutation controls until the save completes.                                 |
| Externally deleted cookies appear current            | The editor retains a fallback snapshot after browser deletion and offers reload against that snapshot.                                                                            | Mark the record unavailable, retain the draft, and disable stale operations.                  |
| Netscape imports change domain scope                 | Standard include-subdomains flags are interpreted using the old extension's inverse convention.                                                                                   | Honor standard flags by default and require an explicit old-CQM compatibility option.         |
| Background replies require newer Chromium            | Review of the new coordinator found Promise-returning message listeners would not reliably reply on the declared older Chromium targets.                                          | Use callback responses and an explicit `return true`; test a callback-only runtime.           |

The initial GitHub build also exposed an artifact-upload configuration error:
the upload action skipped WXT's hidden `.output` directory. The workflow now
explicitly includes hidden files for its narrowly selected ZIP and checksum
paths.

## Verification and limits

Regression coverage lives alongside the core, gateway, mutation coordinator,
browser UI, and native Firefox checks. See [the verification record](verification.md)
for final test counts and browser versions.

The background queue coordinates Cookie Loom pages; it cannot make browser
cookie operations transactional with websites, browser settings, or other
extensions. Cookie writes still require stale-state checks and safe failure
handling. Signed installation, minimum-version browsers, and native permission
dialogs remain manual release checks.
